# Library Cover Store · 封面模板商店

[Library Cover Studio](https://github.com/HappyQuQu/library-cover-studio) 的公开社区模板仓库。在应用「模板商店」中预览、下载社区设计，一键加入自己的模板库。

模板使用与应用导出 ZIP 相同的 JSON 和预览图。每套模板独立打包，独立累计全站下载次数；商店更新不会覆盖用户已经编辑的本地模板。

社区模板统一在本仓库维护，每个模板文件夹中的 `template.json` 和 `preview.jpg/png/webp` 是发布源文件。应用仓库只保留启动和默认还原所需的七套内置模板与示例海报；社区模板不随应用镜像打包。ZIP 通过 `scripts/publish.py build` 生成，不提交合集、高清评审图或一次性生成脚本。

## 使用模板

1. 在 Library Cover Studio 打开「模板商店」。
2. 搜索模板、查看预览和尺寸，点击「下载并添加」。
3. 下载成功后，模板立即出现在「模板库」、设计器及自动化任务的模板菜单中。
4. 已添加同一版本时直接「打开模板」。有新版时显示当前版本、最新版本、更新说明和更新按钮。
5. 未修改的本地模板会原地更新，保留模板 ID 和任务引用，可从历史回退。已编辑、已锁定或旧安装记录缺少原始指纹时，会保留原模板并添加新版副本。

也可以在 [Releases](https://github.com/HappyQuQu/library-cover-store/releases) 下载单套模板 ZIP，在应用「模板库 → 导入模板」中手动导入。不要使用 GitHub 自动生成的整个仓库 Source code ZIP。

## 提交模板

可以选择两种制作方式：从应用导出现有设计，或克隆仓库，用 Codex、Claude Code 等 AI 工具制作新模板。完成后都按下面的文件格式、校验和 Pull Request 流程提交。

### 方式一：从应用导出

在应用「模板库」找到设计，点击「导出」。解压下载的 ZIP，得到 `template.json`、`preview.jpg`，以及模板使用的自定义字体目录 `fonts/`（如有）。请将这些文件一起提交；商店发布的 ZIP 会保留字体，下载导入后自动加入应用的字体管理。

### 方式二：克隆仓库，用 AI 制作

无需先在设计器中手工搭建：把这个项目交给 Codex、Claude Code 等 AI 工具，参考现有模板生成可编辑的设计。

1. 克隆本仓库，在 AI 工具中打开 `library-cover-store` 项目目录：

   ```sh
   git clone https://github.com/HappyQuQu/library-cover-store.git
   cd library-cover-store
   ```

   如果准备贡献，也可以先在 GitHub Fork，再克隆自己的 Fork。直接克隆官方仓库也能在本机制作用于测试的模板；提交时需将改动推送到自己的 Fork，再发起 Pull Request。

2. 让 AI 先阅读本 README 和几套现有的 `template.json`，再说明想要的风格、配色、海报数量、标题布局和作者信息。可以复制以下提示词，并替换方括号中的内容：

   ```text
   请先阅读 README.md 和现有模板，为 Library Cover Studio 制作一套新的封面模板。
   设计需求：[填写风格、配色、海报数量和标题布局]
   模板名称：[填写名称]；作者：[填写名称和主页]；初始版本：1.0.0。
   在仓库根目录创建独立模板文件夹，提供 template.json 和一张 preview.jpg/png/webp。
   参考现有模板的 Fabric 画布结构，canvasJson 必须是 JSON 字符串，保留标题变量和海报变量，
   让设计可以在应用中编辑并用于自动化。
   填写 version、author、description 和 changelog；JSON 与预览图合计不超过 5 MB。
   使用自定义字体时保留应用导出的 fonts 清单与字体文件，含字体的包总计不超过 64 MB。
   预览图必须来自实际模板渲染，与设计一致。
   同步更新 GALLERY.md；模板数量变化时更新 README.md 中的数量和列表。
   更新已有模板时保留文件夹名称，并提高版本号。
   运行 python3 scripts/publish.py check 和 python3 scripts/publish.py build，
   再将生成的单套 ZIP 导入 Library Cover Studio，检查编辑、预览和自动化渲染。
   若无法完成渲染验证，请说明尚待验证的项目。
   完成后说明改动文件和验证结果，并准备 Pull Request 描述。
   ```

3. 根据 AI 的结果继续调整，按下文校验、打包，再导入应用检查。Store 仓库提供模板示例与打包校验；实际预览图可在 Library Cover Studio 导入设计、保存并导出后取得。需要 AI 自动渲染时，可同时提供 Studio 项目中的模板渲染代码。
4. 提交模板文件夹、图鉴和必要的 README 更新，向本仓库发起 Pull Request。AI 生成的模板同样需要通过校验，并确认预览与实际渲染一致。

### 2. 建立模板文件夹

Fork 本仓库，在仓库根目录创建一个有辨识度的文件夹，将解压后的文件及 `fonts/` 目录（如有）一起放进去：

```text
library-cover-store/
├── 胶片放映/
│   ├── template.json
│   ├── preview.jpg
│   └── fonts/（使用自定义字体时）
├── 票根收藏/
│   ├── template.json
│   └── preview.jpg
├── scripts/
└── .github/
```

- 一套模板一个文件夹，不要提交合集，也不要把 ZIP 放进源码仓库。
- JSON 必须叫 `template.json`；预览图必须是 `preview.jpg`、`preview.jpeg`、`preview.png` 或 `preview.webp`，只保留其中一张。
- **文件夹名称是模板的稳定身份**。更新时修改原文件夹里的文件，不要重命名文件夹，否则会作为新模板统计下载次数。
- JSON 的 `name` 是商店显示名称，可以修改。`description` 可以写作者、设计特点、海报数量、字体及最低应用版本等说明。
- JSON 与预览图合计不超过 **5 MB**；画布宽度为 100–4000、高度为 100–6000，名称不超过 100 字符。
- 建议使用应用导出的文件，不要把 `canvasJson` 从字符串改成对象。预览图应与模板内容一致。
- 自定义字体会由支持随包字体的应用自动导出、随商店 ZIP 分发并在导入后安装，已有字体按内容复用；同名但内容不同的字体会保留两份并调整模板引用。请确认字体允许再分发。系统字体及其他外部资源不会自动打包。
- 含字体的模板包（压缩前后）总计不超过 **64 MB**，单个字体不超过 **50 MB**，最多 16 项字体依赖；JSON 与预览图仍合计不超过 5 MB。
- `template.json` 的可选 `fonts` 数组记录实际使用的字体，格式为 `{"family":"字体名","file":"fonts/<sha256>.ttf","sha256":"64 位小写 SHA-256"}`。支持 TTF、OTF、WOFF、WOFF2；字体文件要直接放在 `fonts/` 中，文件名仅使用英文字母、数字、下划线和连字符。分组及局部文字样式的字体也需声明，不要添加未使用的字体或软链接。建议直接保留应用导出的清单和文件。
- 不要上传 API Key、账号密码、媒体服务器地址或其他私人信息。
- 本仓库采用 [MIT License](LICENSE)。请确保你有权以该许可分享模板及预览素材。

JSON 的结构示例（完整设计请从应用导出）：

```json
{
  "name": "胶片放映",
  "version": "1.0.0",
  "author": { "name": "HappyQuQu", "url": "https://github.com/HappyQuQu" },
  "description": "四格胶片封面，使用四张海报。作者：你的名字。",
  "changelog": "首次发布。",
  "width": 1920,
  "height": 1080,
  "canvasJson": "{\"version\":\"6.0.0\",\"objects\":[]}",
  "isPublic": false
}
```

### 版本、作者与更新

这些属性都放在 `template.json` **顶层**，与 `name`、`canvasJson` 并列：

| 字段 | 用途 |
| --- | --- |
| `version` | 模板版本，例如 `1.0.0`、`1.0.1`、`1.1.0`；更新内容时请提高版本号 |
| `author.name` | 作者名称，用于商店展示和搜索 |
| `author.url` | 可选的 HTTP / HTTPS 作者主页 |
| `description` | 模板长期说明：设计、海报数量、所需字体等 |
| `changelog` | 当前版本的更新说明 |
| `minAppVersion` | 可选的最低应用版本，例如 `1.5.0`；低于此版本时无法下载添加 |

在应用设计器中打开「模板信息」，填写信息后保存，再导出 ZIP。导入、复制、导出和历史回退都会保留元数据。版本使用三个非负整数 `主版本.次版本.修订号`；`canvasJson` 中的 `version` 是 Fabric 格式版本，请勿混用。旧模板缺少这些属性时，版本按 `1.0.0` 处理，作者显示为未标注。

更新时保持文件夹名称不变，替换其中 JSON 和预览图；商店按内容指纹检测变化，版本号用于展示，不靠字符串排序决定是否有更新。同一模板各版本 ZIP 的下载次数仍累计，旧附件不会删除。

### 3. 同步更新模板图鉴

**新增或更新模板后，必须同步更新 [GALLERY.md](GALLERY.md)，并在同一个 Pull Request 中提交。**

- 新增模板：在对应分组添加模板条目，展示预览图、商店名称、尺寸、版本、作者、设计说明以及模板文件和原图链接，并补充组内导航。
- 更新模板：同步修改对应条目的信息，确保与 `template.json` 和预览图一致；预览图文件名或格式改变时，也要更新图片链接。
- 模板数量变化时，同步更新图鉴和 README 中的总数、分组数量及模板列表。
- 提交前检查图鉴中的图片能正常显示，模板文件和原图链接可访问。

### 4. 校验并发起 Pull Request

安装 Python 3.10 或更高版本，无需额外依赖：

```sh
python3 scripts/publish.py check
python3 -m unittest discover -s tests -v
```

想在本机检查生成的 ZIP：

```sh
python3 scripts/publish.py build
```

ZIP 生成在 `.store-build/` 中，此目录已被 Git 忽略。将单套 ZIP 导入应用，确认预览和渲染正常。

提交模板文件夹及更新后的 `GALLERY.md`，并向本仓库的 `main` 分支发起 Pull Request。PR 描述请写明模板名称、设计特点、所需字体以及测试使用的应用版本，并确认已同步更新图鉴。自动校验通过、维护者合并后，工作流会自动上架。

只发布根目录中的模板文件夹。以 `.` 开头的目录以及 `scripts`、`tests`、`doc`、`docs`、`examples`、`node_modules` 是保留目录，不用于放模板。

## 自动发布和下载统计

维护者不需要逐个手工创建 ZIP 或 Release：

1. `main` 更新后，GitHub Actions 校验模板并计算内容版本。
2. **只为新增或修改的模板生成 ZIP 并上传**；未变化的模板复用原附件。
3. ZIP 分批存放在 `store-00001`、`store-00002` 等 Release 中，每批最多 **200 个版本附件**，满后自动开下一批。每个 ZIP 始终只包含一套模板。
4. 旧版本附件保留。每套模板的下载次数是其所有已发布版本附件的 GitHub `download_count` 之和。
5. 工作流更新 `catalog` 分支的 `catalog.json`。应用读取这份轻量目录，分页显示 24 套模板，下载时才获取对应 ZIP。

目录和统计约 **每小时**同步一次，GitHub 调度可能延迟，应用还缓存目录 5 分钟。「下载并添加」会获取一次 Release ZIP，重复打开已添加版本不再下载。次数是附件获取次数，不是唯一用户数，也不等于成功导入人数。

为控制 API 写入速率，每次工作流最多上传 **100 个新版本**，依次限速。首次导入数千套模板会分多次执行；未完成的模板在下一次每小时同步时继续发布。失败重试会复用已上传附件。排队的新模板暂不上架；排队更新的模板继续提供已发布旧版本。

删除模板文件夹会将其从商店下架，历史附件仍保留；重新添加相同文件夹可继续累计历史次数。请勿手工删除、覆盖或重命名托管的 Release 附件，否则历史计数可能丢失。

## 维护者首次启用

- 将源码及 `.github/workflows/store.yml` 推送到 GitHub 的 `main` 分支。
- 确认 Actions 已启用，仓库规则允许工作流以 `contents: write` 权限更新 `catalog` 分支并创建 Release。使用 GitHub 自动提供的 Token，应用无需个人 Token。
- 在 Actions 中运行一次 **Validate and publish template store**，或提交第一套模板触发发布。
- `catalog` 分支和 Release 自动生成，不要手工维护 `catalog.json`。没有模板时首次运行也会生成空目录。
- 定时 Actions 长时间无活动可能被 GitHub 停用；如统计停止更新，在 Actions 页面重新启用。发布失败时修复后重新运行，已上传版本会保留。

应用读取的目录：[catalog.json](https://raw.githubusercontent.com/HappyQuQu/library-cover-store/catalog/catalog.json)。欢迎提交模板、反馈问题或完善贡献说明。
